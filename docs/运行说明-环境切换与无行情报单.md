# 运行说明：环境切换与无行情手动报单

本文是给「命令行直接跑测试」用的操作速查。重点覆盖两件事：

1. 如何在多套 YD 环境之间切换（SupremeMM / SYBW 易达仿真）。
2. 无行情环境下如何用固定价格报单（`test_14_manual_price_order`）。

凭据（AppID / AuthCode / 账号密码）只存在于 `config/` 下的本机文件中，本文档不重复记录密码。

---

## 1. 环境与配置文件对照

| 环境 | YD 接入配置 | 账号 CSV |
|---|---|---|
| SupremeMM（有行情） | `config/yd_config.supreme.local.txt` | `config/accounts.supreme.local.csv` |
| SYBW 易达仿真（**无行情**） | `config/yd_config.sybw.local.txt` | `config/accounts.sybw.local.csv` |
| 本机原环境 | `config/yd_config.local.txt` | `config/accounts.yida.local.csv` |

每个 `.local.*` 文件都是本机文件，含凭据，不应提交 Git。

**切换环境 = 换 `--yd-config` 和 `--accounts` 两个参数**，程序不需要重新编译。CSV 和 `yd_config` 都是运行时读取，改完直接重跑命令即可；只有改了 `.cpp/.h` 才需要 `build_windows.bat` 重新编译。

---

## 2. 通用命令模板

所有测试程序都长这样：

```bat
build\bin\<test>.exe ^
  --yd-config config\<环境>.txt ^
  --accounts  config\<账号>.csv ^
  --instrument <合约代码> ^
  [--live]
```

常用参数（来自 `--help`，`src/core/Config.cpp`）：

| 参数 | 说明 |
|---|---|
| `--yd-config` | YD 接入/认证配置文件 |
| `--accounts` | 账号 CSV（username,password,label） |
| `--test-config` | 功能测试配置（默认 `config/test_config.ini`） |
| `--instrument` | 覆盖默认合约 |
| `--live` | 允许真实报/撤单（**缺省一律不报单**） |
| `--price/--volume/--direction/--offset/--keep-working` | 仅 `test_14` 使用 |

## 3. 登录验证（任何环境的第一步）

```bat
build\bin\test_01_connect.exe --yd-config config\yd_config.sybw.local.txt --accounts config\accounts.sybw.local.csv
```

成功标志：

```text
[RESULT] PASS | TCP trade connected
[RESULT] PASS | account login | ... loginTime=...
[RESULT] PASS | static data ready
[RESULT] PASS | history caught up
```

### 登录失败的错误码速查（ydError.h）

| errorNo | 含义 | 处理 |
|---|---|---|
| 19 | `PasswordError` 密码错 | 改账号 CSV 的 password |
| 21 | `InvalidUsername` 用户名不存在 | 核对账号（是否未开通/有前缀/未绑 AppID） |
| 103 | `InvalidLoginInfo` | AppID/AuthCode 配置缺失或非法 |

网络/端口问题不会走到登录：先看 `TCP trade connected` 是否 PASS；连不上则检查 `TradingServerIP` / `TradingServerPort`。

## 4. 列合约与看行情/持仓

```bat
rem 列出柜台全部合约（只读）
build\bin\test_list_instruments.exe --yd-config config\yd_config.sybw.local.txt --accounts config\accounts.sybw.local.csv

rem 某合约行情 + 账号持仓快照（只读，不报单）
build\bin\test_12_market_position.exe --yd-config config\yd_config.sybw.local.txt --accounts config\accounts.sybw.local.csv --instrument au2612
```

`test_12` 日志里 `volume=` 越大说明合约越活跃（有持续行情推送）；`[POSITION]` 列出账号全部持仓。**有行情的环境**用这个挑「活跃 + 该合约投机多仓为 0」的合约跑实盘测试。

## 5. 无行情环境：固定价报单 test_14

SYBW 仿真环境**没有行情接入**，所有依赖实时行情的测试（`test_02/04/10/12` 及 `test_08_1`）都跑不了。为此新增了 `test_14_manual_price_order`：不订阅行情，直接用固定合法价报单。

### 5.1 命令

```bat
build\bin\test_14_manual_price_order.exe ^
  --yd-config config\yd_config.sybw.local.txt ^
  --accounts  config\accounts.sybw.local.csv ^
  --instrument au2612 ^
  --price 1000 ^
  --direction buy ^
  --offset open ^
  --live
```

### 5.2 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--price` | **必填** | 固定报单价（自动四舍五入到合约 Tick 整数倍） |
| `--volume` | 1 | 报单数量 |
| `--direction` | buy | `buy` / `sell` |
| `--offset` | open | `open` / `close` / `closetoday`（平今用 `closetoday`） |
| `--keep-working` | 关 | 加此参数报单后**不自动撤**，留单在柜台 |
| `--live` | 关 | **必须加**才真实报单 |

### 5.3 行为

1. 登录 + 静态数据就绪（**不订阅任何行情**）；
2. 按固定价发一张限价单；
3. 等柜台回报后分支：
   - **拒单**（ErrorNo>0）→ 打印拒单码，FAIL；
   - **全部成交** → 打印 `ALL_TRADED` + 成交价，`OBSERVED`（**不自动平仓**，需自行处理仓位）；
   - **排队**（QUEUING）且未加 `--keep-working` → 自动撤单，确认 `CANCELED` 零成交，PASS；
   - **排队** + `--keep-working` → 留单，`OBSERVED`（提醒去柜台核对）。

### 5.4 典型场景

```bat
rem A. 安全演示：被动价让它排队，随后自动撤单（零成交、不留仓）
... --price 970 --direction buy --offset open --live

rem B. 让它成交并留单观察
... --price 1100 --direction buy --offset open --live --keep-working

rem C. 平掉测试开出的多仓（上期所平今）
... --price 990 --direction sell --offset closetoday --live
```

### 5.5 重要提醒

- `--price` 必须是**合法价**：合约 Tick 的整数倍且在涨跌停区间内。程序会按 Tick 自动取整，但取整后的价格仍需合法。无行情环境看不到涨跌停价，若价格越界柜台会拒单：`errorNo=40`（`YD_ERROR_PriceOutOfLimit`，低于跌停/高于涨停，易达本地拦）或 `errorNo=1026`（交易所自定义错误，已通过本地校验、由交易所拦截）。报被动单时价格必须同时「高于跌停价」且「低于当前市价」，否则要么被 40 拒、要么直接成交。
- `--offset close` / `closetoday` 要求**有对应持仓**，否则柜台拒单（无仓可平），属正常现象。
- 方向/开平组合要自己核对，程序只校验价格和数量，不判断交易意图。
- **成交后程序不会自动反向平仓**——这是刻意设计，避免未经确认的自动操作。成交单留下的仓位需自行处理（见 5.4-C）。
- 报单是真单：`--live` 别漏，也别在生产账户上操作。

## 6. 各测试在「无行情环境」的可跑性

| 测试 | 无行情可用 | 说明 |
|---|---|---|
| `test_01_connect` | ✅ | 纯登录 |
| `test_14_manual_price_order` | ✅ | 固定价报单，本环境专用 |
| `test_08_2_no_position` | ✅ | 需在 `test_config.ini` 设 `ErrorTest.OrderPrice` |
| `test_08_3_market_state` | ✅ | 同上 |
| `test_08_1_insufficient_funds` | ❌ | 需实时 bid/ask |
| `test_02/04/10/12` | ❌ | 需实时行情 |
| `test_05/06/07/09/11` | ✅ | 本地监控/校验，不依赖行情 |

`test_08_2/08_3` 无行情时的后门：`config/test_config.ini` 里把 `ErrorTest.OrderPrice=0` 改成正的合法价即可绕过行情（见 `src/tests/TestCases.cpp` 的 `runErrorMessageCase` 预检）。

## 7. 目录与证据

每次运行在 `output/<时间戳>/` 下按测试项和账号分目录生成 `test.log` 和顶层 `summary.csv`。日志统一带 `TEST/SYSTEM/LOGIN/CONNECTION/TRADE/ORDER/ORDER_RESULT/MONITOR/ERROR/RESULT` 等标记，便于录屏和事后追溯。
